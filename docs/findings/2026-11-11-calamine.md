# Finding: calamine for spreadsheet previews: licences, dependencies and speed (2026-11-11)

## Question

Step O1 of the [video and Office plan](../plans/2026-11-07-video-and-office-previews.md). The Office previews read
spreadsheets with calamine, and docx and pptx with the `zip` and `quick-xml` crates it brings in. Three decisions
depend on facts checked here:

1. **Can calamine ship?** Its licence and its dependencies' licences must pass `cargo deny`. If not, the plan
   stops.
2. **Can docx and pptx use calamine's `zip` and `quick-xml` directly,** at the same versions, so nothing more is
   built?
3. **How should the preview read a big sheet?** It needs the first 2000 rows (`Limits::max_rows`). The choice is
   calamine's cell reader, which can stop at row 2000, or `worksheet_range`, which loads the whole sheet.

## Method

Dev machine: 12th Gen Intel Core i7-12650H (16 CPUs), 31 GiB RAM, Ubuntu, Linux 6.8.0-149, rustc 1.99.1.
calamine 0.38.0, zip 9.5.1, quick-xml 0.42.0, cargo-deny 0.20.2, openpyxl 3.1.5, LibreOffice 24.2.7.2.

**Dependencies and licences:**

```
cargo fetch                       # after adding calamine, zip and quick-xml to Cargo.toml
cargo tree --offline -p finder-core -e normal --depth 3
cargo deny --offline check licenses bans sources
# crates the lock file gained:
diff <(git show HEAD:Cargo.lock | awk '/^name = /{n=$3} /^version = /{print n, $3}' | sort) \
     <(awk '/^name = /{n=$3} /^version = /{print n, $3}' Cargo.lock | sort)
```

**Speed:** the scripts are in [scripts/2026-11-11-calamine-measure/](scripts/2026-11-11-calamine-measure/).

```
python3 -I docs/findings/scripts/2026-11-11-calamine-measure/make_xlsx.py DIR
soffice --headless --convert-to ods --outdir DIR DIR/big.xlsx
cd docs/findings/scripts/2026-11-11-calamine-measure
CARGO_TARGET_DIR=/tmp/calamine-measure cargo run --offline --release -- DIR/small.xlsx DIR/big.xlsx DIR/big.ods
```

- **Files**, made by openpyxl:
  - `big.xlsx`: 100,000 rows × 20 columns, 8.6 MB. Each row has text (500 different values, so shared strings),
    whole and decimal numbers, a date and a formula, plus a second sheet.
  - `small.xlsx`: the same with 200 rows, 23 KB.
  - `big.ods`: `big.xlsx` saved as ods by LibreOffice, 9.0 MB.
- **Cases**, each the median of 9 runs, opening the file each time:
  - `names`: open the workbook and list its sheets.
  - `cells`: xlsx only. Open, then read the first sheet with `worksheet_cells_reader`, stopping at row 2000, and
    turn each cell into text as the preview would.
  - `range`: open, load the whole first sheet with `worksheet_range`, and turn its first 2000 rows into text.
- **Load average** was 3.8 before the xlsx runs and 3.4 before the ods runs: another session was busy.

## Results

**Licences:** `bans ok, licenses ok, sources ok`. The only warning was the existing one about `BSD-2-Clause`
being allowed but unused.

| crate | version | licence |
|---|---|---|
| calamine | 0.38.0 | MIT |
| zip | 9.5.1 | MIT |
| quick-xml | 0.42.0 | MIT (already in the lock file) |
| atoi_simd | 0.18.1 | MIT OR Apache-2.0 |
| debug_unsafe | 0.1.4 | MIT OR Apache-2.0 |
| codepage | 0.1.3 | Apache-2.0 OR MIT |
| encoding_rs | 0.8.35 | (Apache-2.0 OR MIT) AND BSD-3-Clause |
| fast-float2 | 0.2.4 | MIT OR Apache-2.0 |
| constant_time_eq | 0.6.1 | CC0-1.0 OR MIT-0 OR Apache-2.0 |
| typed-path | 0.13.0 | MIT OR Apache-2.0 |
| zeroize, zeroize_derive | 1.9.1, 1.5.0 | Apache-2.0 OR MIT |
| zopfli | 0.8.3 | Apache-2.0 |

**Dependencies:** the lock file gained the 12 crates in the table under calamine (306 → 318 entries).
- `cargo deny` warns about the same duplicate versions as before: base64, miniz_oxide, signal-hook, syn and
  windows-sys. The new crates add no duplicates.
- `zip` pulls in zopfli, zeroize, constant_time_eq and getrandom. calamine itself asks for zip's `deflate`
  feature, so they can't be left out.
- calamine's `dates` feature (chrono) isn't needed. Cells formatted as dates still come back as
  `DataRef::DateTime`, and `ExcelDateTime::to_ymd_hms_milli()` gives the date without chrono.

**Speed** (ms):

| file | `names` | `cells` (stops at row 2000) | `range` (whole sheet) |
|---|---|---|---|
| small.xlsx (200 rows) | 0.2 | 3.9 (2.6–5.4) | 2.3 (1.9–3.1) |
| big.xlsx (100,000 rows) | 0.2 | **21.1** (19.2–23.3) | 804.0 (762.9–986.2) |
| big.ods (100,000 rows) | 1119.8 | n/a | 1192.1 (1138.7–1369.8) |

Every `cells` and `range` run read 4000 cells from `small.xlsx` and 40,000 from the big files.

## Conclusions

- **calamine can ship:** MIT, and every new crate is under a licence `deny.toml` already allows.
- **docx and pptx use `zip` 9 and `quick-xml` 0.42 directly,** the versions calamine uses, so nothing more is
  built. quick-xml was already in the lock file.
- **xlsx previews use the cell reader.** It stops at row 2000, so a 100,000-row sheet takes 21 ms instead of
  804 ms (38× faster). On a small sheet both take a few milliseconds.
- **ods has no cell reader,** and opening it parses the whole document: 1.1 s just to list the sheets of the
  100,000-row file. calamine runs inside `tos`, not as a separate program, so it can't be stopped part-way.
  While it reads, the preview worker is busy and a newer request waits. That's the same as decoding a very
  large image today. A typical ods is far smaller; that's an **estimate**, as no real ods files were measured.
- **Not measured:**
  - `.xls`: it can't hold 100,000 rows (65,536 at most), and calamine has no cell reader for it either, so it
    loads whole sheets like ods.
  - `.xlsb`: LibreOffice can't write it, so there's no test file. calamine has a cell reader for it, but without
    a file to test against, the preview loads its sheets whole.
  - Real spreadsheets with styles, charts and many sheets. openpyxl's files are plain.
