# Finding: WebP instead of GIF for the demo (2026-11-13)

## Question

The user saw that the Ghostty demo's pictures looked about as good as xterm's. Was the GIF format the limit, and
would another format show the full-colour pictures? Which format the README uses depends on it.

## Method

Dev machine (Ubuntu 24.04), ffmpeg 6.1.1 (encoders `libwebp_anim`, `apng`, `gif`; `gifski` not installed or
packaged), Pillow 12.3.0, Ghostty 1.3.1, `tos` built from `c5a1a39`.

- **One recording:** `python3 scripts/demo/record.py --no-claude --keep`, the finder part only (67 s).
  - That run's GIF was made as in [the Ghostty finding](2026-11-13-ghostty-demo.md): a palette from marked frames
    with bayer dithering at scale 4, with captions.
- **WebP from the same raw video,** without captions:
  - lossless after `mpdecimate`, with `-fps_mode vfr`
  - lossless at a steady 15 frames a second (`fps=15`)
  - lossy, at `-quality 90` and `-quality 75`

  Every encode used `-c:v libwebp_anim -compression_level 6 -loop 0`.
- **Frame times:** read from the WebP container (each `ANMF` chunk's 24-bit duration), and with Pillow.
- **Looking:** the frame shown at 65 s (`sunset.png`) and at 26.5 s (the video's frame), cropped, side by side.
- **The full demo:** `python3 scripts/demo/record.py --out <file>.webp`, then the same checks.

## Results

**Sizes,** for the 67 s finder part:

```
GIF (captions, marked-frame palette)          699 553 bytes
WebP lossless, after mpdecimate, vfr          436 054
WebP lossless, steady 15 fps                  436 054   (114 frames: libwebp merges repeated ones)
WebP lossy, quality 90                        676 470
WebP lossy, quality 75                        488 080
```

**Frame times:**
- **From the container:** 114 frames, 66.999 s (steady) and 66.915 s (vfr). The first durations were
  `1466, 67, 67, 66, 67, 67` ms, and the longest was 4067 ms (the last picture held).
- **From Pillow:** a duration of 0 for every frame of the same files. So check WebP timing in the container, not
  with Pillow.

**By eye:**
- **The GIF:** visible rings in the sunset's sky, and dither in the glow around the Mandelbrot set.
- **The lossless WebP:** smooth in both, the same as the screen.

**The full demo, in lossless WebP:**

```
1 175 366 bytes, 260 frames, 94.532 s, 832x618; last frame 3999 ms; Claude 75.9–89.5 s shown at 2x
```

A GIF of a comparable full run (an earlier recording) was 971 344 bytes.

## Conclusions

- **The GIF was the limit.** Its 256 colours undo most of what Ghostty's full-colour pictures add. Lossless WebP
  keeps every pixel.
  - **Finder only:** WebP is 38% smaller than the GIF.
  - **The whole demo:** WebP is 21% bigger than the GIF. Claude's part has more changing text, which costs more
    when lossless.
- **Lossy WebP isn't worth it:** quality 90 is barely smaller than lossless.
- **Let libwebp merge repeated frames,** by encoding at a steady 15 fps. That's simpler than `mpdecimate`, and the
  last frame keeps its time.
- **Unknown:** whether GitHub shows an animated WebP in a README. It hasn't been checked on GitHub itself. This
  is an **estimate**, based on browsers playing animated WebP (current Chrome, Firefox and Safari) and GitHub
  showing image files through `<img>`. Check after pushing. If it doesn't play, `--out docs/images/finder-demo.gif`
  makes the GIF.
