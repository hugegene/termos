# Finding: nano's keys inside tos (2026-11-13)

## Question

The user asked to fall back from Neovim to nano, then vim, when Neovim is missing. Which of nano's keys does
`tos` take before nano sees them? And do `tos`'s editor keys (`Ctrl+s` save, `Ctrl+e` close) work in nano? The
fallback order and the hints depend on it ([editor keys plan](../plans/2026-11-13-editor-save-keys.md)).

## Method

Dev machine (Ubuntu 24.04), GNU nano 7.2 (`nano --version`), `tos` 0.4.2 (`target/release/tos`, with
`Ctrl+s` handed to editors `tos` starts).

- **A throwaway session:** `TOS_SOCKET_DIR`, `TOS_STATE_DIR` and `HOME` under `/tmp/tosnano.*`, started with
  `tos attach -b nanocheck`.
- **nano's help:** `tos action new-pane -- nano -I` (built-in keys only, no nanorc). Then `tos action write`
  sent `^G` (byte 7) and `^V` (22) to page, and `tos dump-screen` saved each page (24 pages).
- **A real save:** `nano -I <file>` in a new pane, typing `hello` (`write-chars`), then `^S` (19), then reading
  the file. Then `^Z` (26), and reading the screen.
- **nano's options:** `nano --help` for its rc-file flags.
- **`tos`'s keys:** compared with [the editor keys finding](2026-11-13-editor-keys.md) (`keys.rs:116`).

## Results

**nano's keys, from its help** (each with its alternative in brackets):

```
^G (F1) help   ^X (F2) close   ^O (F3) write out   ^R (Ins) insert file   ^W (F6) search   ^\ (M-R) replace
^K (F9) cut    ^U (F10) paste  ^T execute          ^J (F4) justify        ^C (F11) position ^/ (M-G) go to line
^Q search backward   ^B ^F ^P ^N ^A ^E (arrows, Home, End)   ^Y ^V (PgUp, PgDn)   ^H (Bsp)   ^D (Del)
M-U undo   M-E redo   M-A (^6) mark   M-6 copy   M-Q M-W next match   M-T M-J M-D M-V M-} M-{ M-3 M-: M-;
M-- M-+ scroll a line   M-, M-. switch buffer   M-7 M-8 blocks   M-9 M-0 paragraphs   M-\ M-/ first/last line
toggles: M-S soft wrap, M-N line numbers, M-P whitespace, M-Y colour, M-H smart home, M-I auto indent,
         M-K cut to end, M-L hard wrap, M-O tabs to spaces, M-M mouse
"Suspend the editor" has no key
```

**Live keys:**

```
"hello", then ^S   → file contains "hello"; status "[ Wrote 1 line ]"   (^S saves, though the help lists ^O)
^Z                 → status "[ To suspend, type ^T^Z ]"                 (doesn't suspend)
```

**nano's options:** `-I, --ignorercfiles` and `-f, --rcfile=<file>` ("use only this file for configuring nano").

## Conclusions

- **Saving and closing work in nano inside `tos`.** `Ctrl+s` reaches nano, because `tos` hands it to editors
  it started, and saves. `Ctrl+x` closes, and `tos` doesn't use it.
  - `Ctrl+e` is nano's "end of line", so `tos`'s `Ctrl+e` close doesn't apply in nano unless `tos` rebinds it.
- **What `tos` hides from nano**, with what's left:
  - `^G` help → `F1`
  - `^O` write out (save as) → `F3`
  - `^T` execute, and the `^T^Z` suspend → none
  - `^N`, `^P`, `^B`: line and character moves → the arrows
  - `^H` backspace → the Backspace key
  - `^Q` search backward → `M-Q` and `M-W` step through matches
  - the toggles under `M-N`, `M-H`, `M-I`, `M-O`, `M-J`, `M-K` and `M-L`, which `tos` uses for panes and tabs;
    `M--` and `M-+` (scroll a line); and Alt+arrows → none, but they're options, not editing
- **`^Z` is safe:** it doesn't suspend nano, unlike Neovim's `Ctrl+z`.
- **`tos` could give nano its own keys**, with `--rcfile=<tos's file>` (`bind ^E exit main`, `bind ^Z undo main`,
  `bind ^Y redo main`), as it gives Neovim `-u`.
  - That ignores the user's own `~/.nanorc`, as `-u` ignores their Neovim config.
  - `Ctrl+e` would no longer go to the end of the line; End still does.
- **Unknown:** a Mac's `nano` is pico (since macOS 12.3), which has no `--rcfile`, and its keys weren't
  checked. Older GNU nano (before 4) may not save on `^S`.
