# Plan: build steps 0–3 (setup → core → multiplexer → daily driver)

**Status:** in progress · **Date:** 2026-11-03 · **Part of:** [rebuild plan](2026-11-03-rebuild-plan.md) §11 ·
**Findings:** [dependencies and licenses](../findings/2026-11-03-dependency-licenses.md); a step 0 finding on the
toolchain and the `alacritty_terminal` API:
[step 0 toolchain and API](../findings/2026-11-04-step0-toolchain-and-api.md).

## Decision

Build steps 0–3 in **this repo**, as a Cargo workspace at the root. The prototype files stay where they are.

| Topic | Choice |
|---|---|
| **Working name** | **`tb`**, a placeholder until the product name is chosen (rebuild plan open question 1). Renaming means a search and replace of the binary and crate names |
| **Crates** | `crates/alacritty_terminal`: the fork, an unmodified copy of 0.26.0<br>`crates/finder-core`: listing, file types and preview data (shared later with the phone API)<br>`crates/tb`: one binary holding the client, server and CLI |
| **Process model** | **One server process per session** (like zellij). It listens on `$XDG_RUNTIME_DIR/tb/<session>.sock`; the folder is `0700` and the server checks each peer's user ID |
| **Concurrency** | **Plain threads and channels, not tokio.** `alacritty_terminal`'s PTY event loop is thread-based, and a Unix socket with a few clients doesn't need async. tokio comes in with the daemon |
| **Who draws** | **The server draws.** For each client, the server builds a `ratatui` buffer (tab bar, panes, borders, status line), compares it with what that client already shows, and sends only the changed cells as terminal output. The client just writes those bytes |
| **Client input** | `crossterm` puts the terminal in raw mode with the alternate screen, mouse, bracketed paste and focus events (plus kitty key disambiguation when supported). It parses keys and sends them as structured events |
| **Pane** | `alacritty_terminal` `Term` + its PTY + its event-loop thread. Answers to terminal queries go back to the PTY |
| **Keys to programs** | Our own xterm-style encoding: modifier codes, application-cursor mode, bracketed paste, focus in/out, and SGR and normal mouse reports |
| **Our keys** | Prefix **Ctrl+B** (the tmux convention; pressing it twice sends a real Ctrl+B). It isn't configurable yet; config is step 6 |
| **Mouse** | Click to focus; click tabs; drag borders to resize; wheel scrolls back through history; drag to select text and copy |
| **Finder** | A built-in pane type, drawn by the server. Its preview area becomes an embedded Neovim terminal while editing |
| **Copy mode** | `alacritty_terminal`'s vi mode, selection and regex search; copying goes to the user's clipboard through OSC 52 |

### Prefix keys (Ctrl+B, then …)

| Key | Action | Key | Action |
|---|---|---|---|
| `c` | new tab | `%` or `\|` | split right |
| `n` / `p` | next / previous tab | `"` or `-` | split down |
| `1`–`9` | go to tab | arrows or `h` `j` `k` `l` | move focus |
| `x` | close pane (asks y/n) | `H` `J` `K` `L` | resize |
| `z` | zoom pane | `[` | copy mode (step 3) |
| `f` | open the finder tab | `d` | detach |
| `?` | help | `Ctrl+B` | send Ctrl+B |

### CLI

```
tb [-s NAME]                    attach to session NAME (default "main"), creating it if needed
tb ls                           list sessions
tb kill [-s NAME]               end a session
tb finder [DIR] [-s NAME]       open a finder tab
tb action [-s NAME] <new-tab|split|focus|close|zoom|resize|go-to-tab|write|detach> ...
tb list-panes [-s NAME] [-j]    panes with id, tab, title, size, focus
tb dump-screen -p ID [--full]   a pane's text (--full includes scrollback)
```

`list-panes`, `dump-screen` and `action write` exist from step 1, because the automated tests use them. That's
how we tested the prototype with `zellij action`.

## Options considered

| Topic | Option | Verdict |
|---|---|---|
| Concurrency | tokio (as listed in the rebuild plan) | Not for the session server; we use threads and channels. It fits the thread-based PTY loop and needs fewer dependencies |
| Who draws | Client draws from cell data | ❌ Larger messages, and the logic would be split across two processes |
| | **Server sends terminal output** (like tmux) | ✅ Thin client; one place to fix drawing bugs |
| Sessions | One server for all sessions (tmux) | ❌ One crash takes down every session |
| | **One server per session** (zellij) | ✅ |
| Prefix | Ctrl+A | ❌ Clashes with "start of line" in shells |
| | Ctrl+Space | ❌ Clashes with completion in Neovim; hard to type on phones |
| | Alt+ keys | ❌ Clash with the prototype editor keys; awkward on phones |
| | **Ctrl+B** | ✅ Widely known from tmux |
| Fuzzy filter | `frizbee` | Later, with recursive search. Step 1 filters only the current folder, so a simple subsequence match is enough |
| Image preview | `ratatui-image` | Step 5 (real images through the client's terminal). Step 1 draws its own coloured half-blocks |
| Logging | `tracing` | Not yet: `alacritty_terminal` logs through `log`, so the server uses `log` with a small file logger |

## Steps

Sizes are **estimates**.

### Step 0: setup

- [x] Install Rust with rustup (stable, plus clippy and rustfmt). The user ran it; rustc 1.99.1.
- [x] Workspace `Cargo.toml`, `crates/*`, `.gitignore` (`/target`), `rust-toolchain.toml`.
- [x] Fork: copy `alacritty_terminal` 0.26.0 **unmodified** from its published crate into
      `crates/alacritty_terminal`, with `LICENSE-APACHE` and an `UPSTREAM.md` naming the version and upstream
      commit. Use it through `[patch.crates-io]`.
  - **This differs from the rebuild plan's checklist**, which asked for "full upstream git history". Importing
    Alacritty's whole history would bloat this repo. Recording the exact upstream commit keeps merges
    traceable. Revisit if the fork moves to its own repo.
- [x] `deny.toml` with the license allow-list from the rebuild plan §7; `about.toml` + `about.hbs` →
      `THIRD_PARTY_NOTICES.md`; `cargo-deny` installed.
- [ ] Install `cargo-about` (needs `cargo install --locked cargo-about --features cli`, run by the user) and
      generate `THIRD_PARTY_NOTICES.md`.
- [x] CI: `.github/workflows/ci.yml` running fmt, clippy, tests and `cargo deny check`. There's no remote yet,
      so it won't run until one exists.
- [x] Finding `docs/findings/2026-11-04-step0-toolchain-and-api.md`: rustc version, MSRVs, the parts of the
      `alacritty_terminal` API we rely on, and `cargo deny` results.
- **Done when** `cargo build`, `cargo test` and `cargo deny check licenses` pass on an empty `tb`.

### Step 1: core (~2.5k lines)

- [ ] Protocol: length-prefixed `postcard` frames, with a version check on connect.
- [ ] Server: socket, peer check, per-client writer threads, the central loop and frame-rate-limited redraws.
      Daemonised with `setsid`, logging to `$XDG_STATE_HOME/tb/<session>.log`.
- [ ] Client: raw mode, input forwarding, resize, detach, and terminal restore on any exit.
- [ ] Panes: spawn the shell with `TERM=xterm-256color`, `COLORTERM=truecolor`, `TB_SESSION` and `TB_PANE_ID`.
      Draw the grid with colours, attributes, wide characters and the cursor. Handle title, bell and child exit.
- [ ] Key, paste, focus and mouse encoding to programs.
- [ ] CLI: `ls`, `kill`, `list-panes`, `dump-screen`, `action write`.
- [ ] Finder tab:
  - file list (folders first, hidden files toggled with `.`, `/` filter, mouse)
  - previews: Markdown, code (syntax colours), plain text, CSV table, HTML (via Markdown), images (half-blocks),
    folders, and file info for anything else
  - Enter opens Neovim in an embedded terminal, using the prototype's notepad config
  - refresh when the folder changes (`notify`)
- **Done when** it matches today's prototype: attach and detach work, the finder previews and edits, and the
  automated tests pass.

### Step 2: multiplexer (~1.5k lines; total 3–5k)

- [ ] Tabs: new, close, next/previous, go to, rename; a clickable tab bar.
- [ ] Splits: right and down; focus by direction or click; close; zoom; resize by keys and by dragging borders.
- [ ] One layout size per session, following the client that typed last; other clients see it padded or clipped.
- [ ] CLI `action` covers all of the above.
- **Done when** these work by keys, by mouse and by CLI, with tests for the layout logic.

### Step 3: daily driver (~1k lines)

- [ ] Scrollback: the wheel scrolls history (when the program isn't using the mouse); a position indicator;
      typing jumps back to the bottom.
- [ ] Copy mode: vi motions, `v`/`V` selection, `y` to copy, `/` and `?` search with `n`/`N`.
- [ ] Mouse selection: drag; double-click selects a word, triple-click a line; copies on release.
- [ ] OSC 52: copies from copy mode, from mouse selection and from programs' own OSC 52 reach the client's
      clipboard. Programs can't read the clipboard.
- **Done when** we can switch daily use from zellij to `tb`; that call is the user's.

## Testing

- **Unit tests:** layout splitting, closing, resizing and focus by direction; key, paste and mouse encoding.
- **Snapshot tests (`insta`):** rendered frames for fixed layouts and for finder previews.
- **Integration tests:** start a server with a temporary socket folder, drive it through the CLI (`action`,
  `write`, `dump-screen`), and check the output. They never touch real sessions.
- **Manual runs:** in a pseudo-terminal harness and in Ghostty, with session names `tbtest-*`. Never inside the
  user's zellij session.

## Risks

| Risk | Mitigation |
|---|---|
| `alacritty_terminal` API surprises | Read the vendored source first and record it in the step 0 finding |
| Key encoding gaps (unusual keys, kitty protocol) | Legacy xterm encoding now, kitty protocol later; unit tests per key |
| Rendering differences between terminals | Plain colours and attributes only; test in Ghostty and Terminator |
| Network access from my shell is sandboxed | The user installs Rust and runs `cargo fetch` once; I build offline. New dependencies need another fetch |
