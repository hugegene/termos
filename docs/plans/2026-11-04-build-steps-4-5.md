## Decision

### Step 4: persistence (reboot recovery)

Sessions come back after a reboot, a crash, `tb kill` or Ctrl+Q, as zellij's do.

- **What's saved** in `$XDG_STATE_HOME/tb/sessions/<name>.json` (folder `0700`, file `0600`):
  - **Tabs:** names, the split layout with its ratios, the focused pane, fullscreen, sync and pane names.
  - **Terminal panes:** the working folder, and the command running in the foreground if it isn't the shell.
  - **Finders:** the folder, the selected entry, hidden files on or off, which side has focus, the preview
    scroll position, and the file open in the editor.
- **When:** every 2 seconds if anything changed, and when the session is killed or quit. The file is written to
  a temporary name and renamed, so a crash never leaves half a file.
- **Not saved:** scrollback and the programs themselves. No multiplexer can bring a process back.
- **Restoring:** attaching to (or starting) a session that isn't running but has a saved file rebuilds it.
  - Shells open in the saved folders, or the home folder if one is gone.
  - A command that was running is **typed at the prompt without pressing Enter**, like zellij's "press Enter
    to run". It's typed once the shell has drawn its prompt, so it isn't echoed twice.
  - Finders reopen where they were. A file that was being edited reopens in Neovim, and Neovim's swap file
    protects unsaved edits.
- **Ending a session:**
  - If the last pane exits (`exit` in the last shell), the saved file is deleted: there's nothing to restore.
  - `tb kill` and Ctrl+Q keep the file, so the session can come back, as with zellij's `kill-session`.
- **CLI:**
  - `tb ls` also lists saved sessions as `name (exited, attach to restore)`.
  - New `tb delete NAME` (alias `delete-session`) forgets a saved session. `--force` also ends a running one.

### Step 5: finder extras

**Real images**, with the kitty, iTerm2 and sixel protocols, and coloured blocks as the fallback.

- **Detection runs in the client**, because each attached terminal can differ. The client checks, in order:
  1. `TB_IMAGES=kitty|iterm2|sixel|blocks` overrides everything.
  2. Inside tmux, zellij or screen (`TMUX`, `ZELLIJ`, `STY`), it uses blocks, because passing images
     through those is unreliable.
  3. It sends one query batch and reads the answers for up to 1 second, stopping at the device-attributes
     answer that every terminal sends. The batch holds a kitty graphics query, a cell-size query (`CSI 16 t`) and a
     device-attributes query (DA1).
  4. **Choice:** kitty if it answered; iTerm2 if `TERM_PROGRAM` is `iTerm.app` or `WezTerm`, or
     `LC_TERMINAL=iTerm2`; sixel if the device attributes list `4`; otherwise blocks.
  5. **Cell size in pixels** comes from the terminal size ioctl, else the `CSI 16 t` answer. Without it, kitty
     and iTerm2 still work (the terminal scales to cells), but sixel falls back to blocks.
- **The protocol version goes to 2.** The client sends its image protocol and cell size when attaching. A
  session started by an older `tb` refuses the new client. `tb kill` ends it, and step 4 restores it.
- **The server encodes per client:**
  - Images are fitted to the preview box and never enlarged. Encoding is PNG for kitty and iTerm2, and our
    own encoder for sixel: a 6×6×6 colour cube with Floyd–Steinberg dithering.
  - Encoding runs on a background thread, and blocks show until it's ready.
  - Encoded images are cached by image, protocol and size.
- **Placing images:** the server tracks which images each client shows, and where.
  - It places an image after the frame's text, and removes it when the preview, tab or layout changes.
  - kitty images are deleted by id.
  - sixel and iTerm2 images are erased by resending the cells under them.
  - An image is placed again if text was drawn over it.
  - With the help screen open, no images are shown.
- **Sharper source:** the preview thumbnail grows from 512 to 1600 pixels on the long side.

**CSV grid editor**, replacing VisiData.

- **Opening:** Enter on a `.csv` or `.tsv` file opens the grid in the preview box. **`E`** opens any text file in
  Neovim instead, so CSVs can still be edited as plain text.
- **Grid keys** (VisiData-like; the prototype's hint was "e edit cell · Alt+s save · q close"):
  - **Moving:** arrows or `h` `j` `k` `l`, PgUp/PgDn, `g`/`G` first/last row, `0`/`$` first/last column.
  - **Editing a cell:** `e` or Enter. In the cell: typing, ←/→, Home/End, Backspace and Delete edit; Enter
    keeps the change and Esc cancels it.
  - **Rows and columns:** `a` adds a row below, `A` a column to the right; `d` deletes the row, `D` the column.
  - **Undo:** `u`, up to 100 steps.
  - **Saving and closing:** Alt+s saves. `q` or Alt+q closes, and asks y/n if there are unsaved changes.
- **The header row** stays at the top. Column widths follow the content (at most 24 characters), and the grid
  scrolls sideways to keep the cursor in view.
- **Saving keeps the file's shape:**
  - same delimiter and line endings
  - quotes only where needed
  - rows of different lengths stay as they are
  - written to a temporary file and renamed, with the same permissions
- **Limits:** UTF-8 files up to 100,000 rows and 20 MB. Larger or non-UTF-8 files show a message pointing to `E`.

## Options considered

| Topic | Option | Verdict |
|---|---|---|
| Restore running programs | Re-run them automatically | ❌ Dangerous (a build, a deploy, `rm`), and zellij asks too |
| | **Type the command, don't press Enter** | ✅ One key to resume, never by surprise |
| `tb kill` | Also deletes the saved layout | ❌ zellij's `kill-session` keeps it; the user is used to that |
| | **Keep it; `tb delete` forgets it** | ✅ |
| Image library | `ratatui-image` (MIT) | ❌ It links LGPL `libchafa` by default and detects in-process, while our server serves several terminals; needs a download |
| | **Our own encoders** (about 500 lines) | ✅ No new crates; we choose the order and the caching |
| kitty placement | Unicode placeholders (images as text cells) | ❌ Needs a 297-entry diacritics table and isn't supported everywhere (e.g. WezTerm) |
| | **Direct placement, deleted by id** | ✅ Works on every kitty-protocol terminal |
| Sixel colours | Median-cut palette | Better, but more code; maybe later |
| | **Fixed colour cube + dithering** | ✅ Simple, predictable |
| CSV editing | Keep VisiData as an external program | ❌ Python dependency; the plan replaces it |
| | **Our own grid in the finder** | ✅ |
